# 可替換的配音、字幕、影片與電子書流程

這份文件隨技能獨立附帶，無需另一技能。先確認Agent當前能力：讀寫本地檔案、看圖、語音生成／接收、影片合成、HTML製作與檢視。若所在環境要求使用指定技能／工具，遵循環境規則；不得模擬未提供的工具。可用Python、Node、SVG／Canvas、瀏覽器渲染、FFmpeg或等效軟體，執行結果才算完成。

## 旁白與時間

- 沿用既有核定音檔，或以已選TTS生成。聲音預設建議而非保證：`zh-TW-HsiaoChenNeural`。Kokoro 與 xu-yaowen-tts 為備選引擎；實測後擇優並記錄採用者。有模型載入成本的本地引擎（如VoxCPM2，載入約25–35秒）應寫batch腳本單次載入後逐句生成，不要逐句呼叫CLI重載模型；生成時固定seed並記錄於timings，保證可重現。此類引擎輸出多為48kHz，混音時一次性重取樣，不要預先逐檔轉檔。
- 使用外部TTS需遵循已授權的內容、目的地與當前權限；不因讀了技能就自動獲得外傳、發布或付款授權。也不重複詢問已清楚授權的操作。
- 可讀旁白、角色對話與畫面文字分開；古文原句、翻譯及改寫標示正確。試配音前時間稱「預估」。
- 用實際句／詞邊界建立SRT與動作觸發。按自然片語斷句，不重疊、不切半詞，確認字型支援與安全區。每幕旁白前後保留合理停頓。TTS引擎偶爾截掉句尾最後一字（VoxCPM2已知），最後一幕收尾至少留2–3秒停留，不要只留0.5秒，避免字幕一結束就斷片；句尾異常先換候選／種子，不要直接進混音。
- 使用者回報「聲音重複」時先`ffprobe`確認容器軌數：多半不是雙音軌，而是鋪軌邏輯重疊（見「音量與合成」段的去重鍵規則）。
- SRT採單行字幕：1920×1080下每行約14–16字為上限，超過就拆成兩條SRT或修稿，不讓播放器自動折行成兩行。
- 字幕拆分函式必須過濾空後半段：遞迴在標點恰為末字時會產出空文字、start==end的零長度cue，驗收前即為錯誤。拆分後以`check_project.py`驗一次。
- 彩色畫面上的字幕不可只放單色字：加半透明圓角底襯，底襯與字色依該畫面明暗選深／淺對比組合（白底線稿用深字、深色元件場景用淺字），不寫死單一配色。
- edge-tts 7.x起`Communicate`的`boundary`預設改為`SentenceBoundary`；需詞級邊界時顯式傳`boundary="WordBoundary"`，否則拿不到逐詞時間。
- 固定片長先修稿、調整停留或重新配音，再考慮少量調速；不預設大量加速。轉場／章節頁／片頭尾都計入正式片長，不能盲目用-shortest截掉內容。
- 語音不可用時交付已完成的無配音版、腳本及明標未實測的時間稿，說明缺項；不得將其稱同步字幕完整版。保留專案可續作。

## 音量與合成

可用FFmpeg作可攜參考工具，或使用等效方案。不要寫死機器路徑與供應商金鑰。若下載相依程式，放專案／環境允許位置並遵循當前權限。

**鋪軌去重以句子ID為鍵**：一句旁白常被拆成多條字幕cue（單行字數上限），鋪音軌時每句只放一次、取該句第一條cue的start。若用`(start,cue)`當去重鍵，拆分句會被鋪兩次，數秒後疊播同句——聽感即雙聲重複，且重疊會讓量測音量虛高、loudnorm基準失真。修法：`first_start.setdefault(line, cue.start)`。此為實測踩過的回歸坑。

旁白可建議約 -16 LUFS、true peak約 -1.5 dBTP。雙遍loudnorm第一遍測量，第二遍帶入input_i、input_tp、input_lra、input_thresh、target_offset；量測實際成片，記錄容差與結果，不能只記目標值。

聲音已對齊到與動畫相同長度後，合成例：

```bash
ffmpeg -i animation.mp4 -i narration.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k -movflags +faststart final.mp4
```

上例沿用已完成H.264視訊。若尚未編碼，採libx264或等效H.264編碼器、yuv420p與指定fps；字幕可先在畫面合成時繪製，避免依賴各平台不一定有的libass。若使用其他字幕方式，仍需檢查繁中字型。必要時同時交付外掛SRT。

單一音軌由各幕語音拼接時，按幕補適量靜音再合成，而不是讓語音依檔案長度無縫壓縮場景。確認AAC起訖、畫面長度與停留一致。

## HTML電子書

只有交付範圍包含電子書時製作。與影片共用已核定的內容與素材：保留原圖版使用同一原圖與裁切；逐筆版使用同一元件的完成態。不要另生不同造型的電子書插圖。

建議單一離線HTML：CSS／JS／圖像或SVG／必要音訊內嵌，不依賴CDN。元件SVG及後製文字須兼顧語意說明；來源有內嵌文字時避免另重複整段文字影響閱讀。

- 支援桌面與手機，正文清楚；圖解可縮放或橫向滑動。
- 有目錄、上一頁／下一頁、鍵盤導覽及可選字級調整，不顯示頁數或分段進度線。
- 有分章則每章內容前有獨立章節頁；不強迫短片／短書分章，不預設固定三章。
- 可使用已生成音訊做逐頁朗讀，不自動播放；換頁停止上一頁。沒有音訊則不放假播放按鈕。
- 列印模式顯示全部內容，而非只有目前可見頁。閱讀位置可本機儲存，處理儲存不可用情況；不加追蹤程式。

## 驗收與交付

檢視每幕開始、繪製中、完成態、換幕及關鍵動作；檢查筆尖貼合、繪製順序、可讀性、主體裁切和填色。至少輸出一張多幕預覽及必要的局部檢查圖。

以ffprobe或等效工具讀實際尺寸、fps、編碼、時長；完整解碼全片以發現截斷／損壞，不只看檔案存在。目標影格數與片長需在實際時間基準容差內。視覺檢查不能單靠解碼成功取代。

電子書實測目錄、翻頁、音訊、手機、字級與列印，記錄測試能力與未測部分。檢查是否真的無外部依賴。尚未做的檢查不能宣稱通過。

交付可用下載檔、字幕、音訊、腳本與必要元件／時間軸；打包相對路徑、版本與重建指令，包含必要字型及素材取得說明。保持原版，不附帳密、私人快取或無關內容。若是規劃／外部生圖模式，精確列出待回傳元件，完成已選交付後等待素材。
