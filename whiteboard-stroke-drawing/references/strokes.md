# 獨立元件與真實逐筆路徑

## 素材建立

列出元件ID、造型參考、視角、朝向、姿勢、附帶道具、遮擋、定位點與使用幕次。完整人物足以白板繪製；只有需要關節活動才拆頭／四肢。會掉落／放下的道具需有獨立版本，避免角色原圖已持一把劍又重疊一把。

保持已選角色設定。點陣生圖請求透明或純白背景、完整主體與無文字；但不要依賴提示詞取得真實SVG、圖層、骨架或筆畫順序。生成PNG後仍需整理或描線。

### 生圖參考流程

生圖在本製作線產出的是**造型參考與描線依據**，不是直接素材；最終畫面來自筆畫路徑，不是生成圖像素。簡潔向量風可跳過生圖、直接以path建構，生圖僅作風格探討。

- **`--ref` 連續生成**：多元件共用風格基準圖作參考輸入，保持角色比例、配色與線條風格一致（image-gen技能的`--ref`即此用途）。
- **生成後的特有關卡**：不只檢查「像不像」，先問「**這個造型能用少量筆畫畫出自然線稿嗎**」。細節爆炸的生成圖（毛髮、複雜紋理、漸層光影）在描線階段會碎線成災——重生時改要求簡潔線條，或降級為簡潔向量風直接建構。
- **重生成上限3次**：超過就帶著當前最佳結果與使用者討論取捨，不要無限迴圈。
- 風格選擇原則：服務逐筆揭露——線條清楚、封閉輪廓、細節適中。未經本製作線實戰驗證的風格不寫成推薦表，先小段試繪再擴展。

簡潔向量風格可直接用path／polyline／Bézier等建立元件；它是已選風格，不是提高效率而默默更換原圖的理由。保留原圖造型的描線要比較外觀、比例與重要細節。

## 手部素材規格

手持筆的手是獨立素材，規格如下（兩支實戰片驗證）：

- **膚色平塗＋實心化**：生圖產出的手常是純線稿或含半透明區塊，需轉成不透明膚色填充；白板影片的手要有存在感，線稿手會融入背景。
- **尺寸跟元件縮放比例走，不是畫布高度百分比**：橫式實測約410px／1080 canvas（≈畫布高度35–40%）。太小沒存在感、太大擋住繪製內容。換版面時勿套畫布高度百分比——直式1080×1920套用會得到約700px大手、蓋住整個元件；正確做法是保持已驗證版面的手:元件寬比（410px手/300px杯 → 直式240px杯配≈330px手），抽幀驗證手與元件比例自然。
- **nib點必須重新標記**：裁切、實心化處理後原生nib座標會失效，處理後目視重新標定，存入專案的registry JSON（含處理後檔案的SHA-256）。渲染時以nib對齊筆尖，不用圖片左上角猜。
- **驗收**：放大檢查筆尖是否貼合筆畫前緣；偏移就修nib點，不要靠調畫面座標補償。

### 旋轉行為

**預設（實戰驗證）：只平移不旋轉**。手部圖永遠同一角度，跟著筆尖位置移動。實作最簡單（單一座標paste）、視覺穩定、永遠不變形；細看手在「滑行」而非「握筆」，畫大弧線時筆桿方向與線條不一致，輕微失真但可接受。

**進階選項（未實戰驗證，選用需自行驗收）：切線旋轉＋角度鉗制**。取當前弧長位置的切線角度，把手部繞nib旋轉，並把角度限制在±40°內。握筆感真實許多，但需另外處理：①折角處角度跳變要平滑平滑濾波；②旋轉超過±45°手會看起來翻過來（避免突然翻手）；③每幀旋轉重採樣的成本。選用此選項時，驗收重點在折角與連續反向線段處。

## 標準筆畫資料

每個元件一個JSON：

```json
{
  "width": 300, "height": 400,
  "strokes": [
    {"id":"outline","points":[[50,60],[90,30],[150,60]],"width":4,"color":"#202c33","closed":false,"fill":null},
    {"id":"detail","points":[[70,90],[130,90]],"width":3,"color":"#202c33","closed":false,"fill":null}
  ]
}
```

上例是有效幾何格式，不是可直接用於所有主題的插畫。`points`為元件本地坐標，筆畫陣列就是順序。曲線先以足夠精度採樣，依弧長計時而不是按點數平均。closed填色需閉合幾何，避免開放線段任意填成大色塊。

SVG可由同一份資料輸出，PNG預覽也由同一資料產生，避免影片和電子書各畫一版。文字保持另一圖層；原圖需要保留文字則另記來源與處理選擇。

## 逐筆渲染參考

1. 預算每筆長度 `L = Σ distance(Pi, Pi+1)`。按繪製時間分配實際弧長，於當前線段插值得到筆尖。
2. 已完成筆畫完整顯示，當前筆畫只顯示累積弧長；下一筆還不可見。抗鋸齒與線寬保持一致。
3. 每筆間安排短抬筆。抬筆時不畫連接線，手部可移向下一筆起點或短暫移開。
4. 填色在輪廓閉合後顯示或分開安排，不讓填色提前透露尚未畫出的物件。
5. 同一筆尖依元件的縮放、旋轉、平移變換到畫面；手部nib也用相同變換定位。不要以手部圖左上角猜筆尖。
6. 原生筆尖點、手部尺寸、旋轉中心與畫面安全區可追蹤；繪製中避免突然翻手或遮字幕。

在SVG／Canvas可用弧長／stroke-dashoffset或路徑採樣；在Python可按同一數據逐幀畫polyline，再送給FFmpeg。這些是可替換的實作方式，不要求特定框架。若本Agent環境有必須遵循的影片規則，先遵循該規則再選工具。

## 文字：中文字不逐筆

中文標題與字卡預設走labels文字層（字型繪製＋淡入），不走逐筆路徑——中文字筆畫數十、每字需獨立手寫體路徑，逐筆寫中文效果差、成本高。字卡在該元件畫完後淡入0.5–0.6秒，位置記入project.json的labels（含x/y/start/role）。這是實戰決策：咖啡教學片的標題與五張名稱字卡全走labels，視覺一致且零額外路徑。英文單字或符號若刻意做手寫感才建路徑；實戰片未驗證，屬未實戰項目。

## 節奏：起畫吃掉靜默

第一個元件的起畫時間可提前進旁白間的靜默段（如片頭句結束後立即起畫），避免數秒空等；每句旁白間隔約3秒，給「畫完＋字卡淡入＋停留」。實戰節奏：每句旁白對應一個元件、畫完即亮字卡、片尾留≥2.5秒總覽停留。

## 先試一個元件

選擇代表性的曲線、封閉輪廓、內部細節與填色，製作短測試並檢視開始、中段、完成畫面。修正筆畫順序、跳筆、筆尖偏移與過快繪製，再擴展其他元件。測試成本不需要變成反覆人工核准。

**渲染前先出全版面完成態靜態預覽圖**：所有元件畫成完成態＋標籤＋實際版面座標，一張圖讓使用者在耗時渲染前確認造型與配置（實戰片的`gen_assets.py`一次產出五杯靜態預覽，使用者確認後才進配音）。造型不對此時改幾何參數即可，成本最低；只驗單元件不驗全版面，渲染後才發現配置問題就貴了。

（驗證記錄：咖啡教學片以此流程一次通過`check_project.py`與完整解碼——欄位拆分、cue≤16字、鋪軌line去重、手部nib對齊、累積式轉場四組規則均實戰有效，後續片子照走即可。）

## 動作與連續性

明確分出draw／move／pose／camera／hold。船上的刻痕跟隨船移動；手持道具分離需明示事件；鏡頭平移不等於世界物件位移。沒有動態情節的圖解不必硬建物理場景。

單筆同時只畫一個物件；既有動作表即可承載幕內多個節拍，避免另維護一套衝突時間軸。自動描邊後的路徑排序與故事合理性是視覺驗收，不是JSON格式通過就完成。

## 畫面累積與轉場

**預設累積式**：新幕在同一畫面繼續加元素，前一幕畫完的元件原位停留，畫面逐步累積成完整圖解。這是逐筆線的天性，沒有空窗期，不需要轉場。新元件的揭露順序服務敘事：旁白說到哪個概念，繪製對應物件。

**開場的空白畫布是合理的**：第一筆開始前畫面就是空白，這是逐筆繪製的自然起點，不是錯誤。

**場景式時間軸（換幕清畫面）附帶規則**：
- 場景間空窗期不得露出空白畫布——上一幕的完成態凍結顯示至換幕，新幕起始0.3–0.4秒與上一幕完成幀交叉淡化後再開始繪製。空白畫布突然取代完成圖是可見瑕疵（此為另一製作線實戰踩過的坑）。
- 換幕時已完成元件要麼隨上一幕凍結淡出、要麼在新幕以完成態直接存在並重新排列，不要消失後又從頭畫一遍（除非敘事上就是重畫，如分步圖解）。
- 畫布底可鋪同色系紋理圖提升質感；純色亦可，保持全片一致即可。

驗收時實際觀看每次換幕前後各0.5秒，確認無空白閃現與元素跳變。

## 彩色圖→線稿→塗色揭露（實測）

適用：先有一張彩色完成態，做「逐筆線稿 → 線條全部完成 → 逐區塗色揭露」的兩幕結構（對標 Puti-AI 白板片的片尾 finale）。實測來源為咖啡片五杯預覽圖（1920×1080 扁平插畫），10秒300幀跑通，驗收為最終幀內容像素吻合＋揭露時序正確。

**核心觀念：塗色不是畫上去的，是揭出來的。** 底層放彩色原圖，上層蓋白紙；蛇形掃描（zigzag）遮罩在區域輪廓內推進，露出的都是原圖正確像素。第二幕時序固定為**線條全部完成後才開始塗色**，不邊畫邊上色。

管線三步：

1. **抽線**：Canny → `approxPolyDP` → 依弧長排序的 polyline 陣列，線稿階段按弧長計時逐筆繪出。
2. **切區域**：顏色分群（kmeans k=8）→ 每個集群跑連通區 → 每個連通區就是一個塗色區域。
3. **揭露時序**：區域依 cx 由左到右排序，時間 ∝ √面積（大塊慢、小塊快）；每區用水平蛇形掃描線（步距≈45px、線寬≈70px）推進，遮罩裁在區域內；已完成區域只記一次不再重算。

實測踩到的六個坑：

1. `cv2.connectedComponents` 只回 2 值，要 stats／centroids 必須用 `connectedComponentsWithStats`（回 4 值）。
2. **Canny 邊線天然有開口**：深色填色與輪廓交界處出不了邊線（實測杯口 6–8px 漏）、文字筆畫邊線全漏。開口讓區域併進背景 → 被「接觸邊界即剔除」規則跳過 → **整塊不上色**。閉合核要 21×21 才勉強封住杯口，對文字完全無解。
3. **正解是顏色分群連通區**：顏色區塊天生封閉、沒有開口問題；且揭露＝複製原圖像素，深色文字筆畫與輪廓本身也是深色集群，會連原始輪廓一起露出，正好補掉線稿的缺口。
4. `labels[i] == i` 是取第 i **列**不是第 i 個元件——shape 會是 (H,)，無報錯靜默錯；正確寫法 `labels == i`。
5. `255 - dilate(edges)` 在 uint8 下溢（變大數），令 `distanceTransform` 全域失效；偵錯要 `.astype` 或用 `255 ^` 前先確認型別。
6. **揭露越界無害**：遮罩劃過界露出的仍是原圖正確像素（界外＝白底）；真正致命的只有「區域漏進背景→被跳過→不上色」。所以區域偵測求「夠封閉」，不用怕「太寬鬆」。

驗收手段：抽 t=線稿完成／塗色中段／最終三幀，比對 nonwhite% 進程（線稿 < 中段 < 完成），再拿最終幀與原圖逐像素比對——不吻合像素應全部是線稿疊在色塊邊緣的 1–2px 描線。

多幕場景式成片（北風與太陽實戰，4幕 39s 一次過 check_project）另踩三個坑：

7. **cv2 讀進來是 BGR，直接餵 rawvideo（-pix_fmt rgb24）會紅藍互換**。白底與黑線是灰階看不出來，只有彩色區錯——實戰中黃太陽渲成藍太陽。送 pipe 前必須 `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`，且要在抽線與分群「之前」轉，全鏈一致。驗證法：取已知顏色區（如太陽）的平均 RGB 與原圖同座標比對，R<B 即中槍。
8. **交叉淡化不得蓋掉新幕的繪製狀態**：淡化期間若直接顯示「淡出的上一幕」，淡化結束當刻新幕已偷偷畫了 0.35 秒，線條會帶著進度跳出來。正確時序＝淡化只在「上一幕完成幀↔全白」之間進行，`t_local < xfade` 時新幕不畫任何東西，淡化完成才以 `t_local - xfade` 起畫。
9. **驗收數值先算預期再比對**：letterbox（圖片高度貼合、左右留白）會讓整幀 nonwhite% 系統性低於原圖——先乘上面積佔比（1620/1920=0.844）再比，才不會把正常值誤判成揭示不全；取樣點落在線稿上會比原圖暗，方向全為變暗且色相不變＝線疊加，不是顏色錯。

（實戰備註：read 工具讀圖在本機多次回錯配圖片，視覺驗收改以像素統計為主——已知顏色點比對＋關鍵幀 nonwhite%＋標題帶暗像素追蹤淡入淡出；成片最終仍需人眼過一遍。）

## 素材規範：生圖端（路徑A，由成功案例反推）

上面的管線對輸入素材有要求，生圖時就照這四條下 prompt，坑根本不出現（本次實測的來源圖即合格範例）：

- **白底、無陰影漸層**：Canny 不被漸層雜訊干擾，kmeans 的「白」集群乾淨切出背景。
- **封閉黑色輪廓線**：區域天然封閉，第 2 號坑直接消失。
- **扁平色塊、有限色數**：kmeans k=8 分群穩定，一個物件＝少數幾個集群。
- **線稿與彩色必須同源**：一律「彩色圖進、線稿出」，絕不兩次獨立生成再對齊。

## 既有圖：路徑B（骨架，未實測）

以下為設計推測，**尚未實戰驗證**，採用前先小段試跑：

- **體檢分流**：取樣色彩數與漸層比例——扁平插畫直接進管線；照片／漸層圖先 `posterize` 量化「壓扁」成色塊圖再進（把 B 轉成 A）。
- **區域偵測 fallback**：壓扁後色塊仍太碎 → 改用 SLIC 超像素代替 kmeans 連通區。
- **抽線分流**：照片沒有手繪輪廓，Canny 出的是碎線 → 換 XDoG 或 ControlNet lineart。此時塗色仍靠原圖遮罩，線與原圖不完全同源只影響線的美感、不影響色。
